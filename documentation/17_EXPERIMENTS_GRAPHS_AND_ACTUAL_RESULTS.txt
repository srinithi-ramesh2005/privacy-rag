1. EMPIRICAL BENCHMARK EXPERIMENTS (benchmark_results.json)
--------------------------------------------------------------------------------
All metrics reported below were experimentally measured on the actual implementation
running with Python 3.13, Qdrant Vector Engine, and `BAAI/bge-small-en-v1.5`.

EXPERIMENT 1: CRYPTOGRAPHIC INTEGRITY & CIPHERTEXT TAMPER DETECTION
  - Objective: Evaluate round-trip encryption/decryption fidelity and verify that bit-level
    tampering is reliably detected by Gate 2 (MMR) and Gate 4 (AEAD).
  - Sample Size: 500 chunks, 200 adversarial tampering trials.
  - Measured Results:
      - Decryption Correctness: 100.0%
      - Mean Encryption Time: 0.0188 ms per chunk
      - p95 Encryption Time: 0.0305 ms per chunk
      - Mean Decryption Time: 0.0104 ms per chunk
      - p95 Decryption Time: 0.0221 ms per chunk
      - Storage Overhead (Raw): 5.85% (exactly 28 bytes per chunk: 12-byte IV + 16-byte tag)
      - Storage Overhead (Base64): 47.42% (due to Base64 4:3 byte expansion)
      - Tampering Trials: 200 trials with single-bit flips
      - Tampering Detected: 200 / 200
      - Tampering Detection Rate: 100.0%

EXPERIMENT 2: PRIVACY LEAKAGE & CROSS-TENANT ISOLATION
  - Objective: Prove that the vector database storage contains zero plaintext chunks and that
    cross-tenant retrieval attempts are strictly prevented.
  - Sample Size: 21 Qdrant points inspected, 150 unauthorized cross-tenant requests.
  - Measured Results:
      - Plaintext Chunks Found in DB: 0 / 21
      - Plaintext Exposure Rate: 0.0%
      - Unauthorized Attempts: 150 attempts across isolated org collections
      - Unauthorized Successes: 0 / 150
      - Unauthorized Decryption Rate: 0.0%
      - Adversarial Tampering Rejected: 100 / 100 (100.0%)

EXPERIMENT 3: RETRIEVAL QUALITY COMPARISON
  - Objective: Measure whether encrypting chunks and verifying Merkle paths degrades vector retrieval.
  - Baseline (Ordinary Plaintext RAG) vs Privacy RAG (Ours):
      - Recall@5: Ordinary = 1.0000 | Privacy = 1.0000 (Difference: 0.000)
      - Precision@5: Ordinary = 0.2600 | Privacy = 0.2600 (Difference: 0.000)
      - MRR: Ordinary = 0.7333 | Privacy = 0.7333 (Difference: 0.000)
      - NDCG@5: Ordinary = 0.8079 | Privacy = 0.8079 (Difference: 0.000)
  - Key Finding: Cryptographic encryption and Merkle proof verification introduce ZERO loss
    in retrieval quality because vector representations are mathematically decoupled from payloads.

EXPERIMENT 4: ANSWER QUALITY & ACCURACY COMPARISON
  - Objective: Evaluate final answer correctness, faithfulness, and unauthorized disclosure prevention.
  - Measured Results:
      - Answer Correctness: Ordinary = 17.69% | Privacy RAG = 42.69% (+25.0% Improvement)
      - Faithfulness Score: Ordinary = 0.879 | Privacy RAG = 0.889 (+0.010)
      - Context Relevance Score: Ordinary = 1.000 | Privacy RAG = 1.000
      - Answer Completeness: Ordinary = 0.6192 | Privacy RAG = 0.8067 (+0.1875)
      - Unauthorized Disclosures Prevented: 1 in Ordinary -> 0 in Privacy RAG
  - Why Privacy RAG Won: Dynamic Boundary Verification and CRAG prevented omission hallucinations
    and excluded ungrounded claims that contaminated ordinary RAG generation.

EXPERIMENT 5: END-TO-END LATENCY & SYSTEM OVERHEAD
  - Measured Results:
      - Vector Search Latency: 27.71 ms
      - Decryption Latency: 0.0396 ms per query
      - Mean End-to-End Latency: Ordinary = 47.41 ms | Privacy RAG = 47.45 ms
      - Total Cryptographic Overhead: 0.04 ms (0.08% overhead)
      - Query Throughput: Ordinary = 21.09 QPS | Privacy RAG = 21.07 QPS
      - Peak Process Memory: Ordinary = 581.13 MB | Privacy RAG = 582.38 MB (1.25 MB difference)

2. GRAPH INTERPRETATION GUIDE FOR PROJECT DEFENSE
--------------------------------------------------------------------------------

Graph 1: `outfolder/module_1_chunking/chunking_line_chart.png`
  - X-Axis: Chunk index (0 to 5)
  - Y-Axis: Chunk character length and semantic cohesion score
  - Observations: Shows fixed-length chunking has higher size variance (stdev 23.31) than semantic
    chunking (stdev 21.78). Semantic chunking achieves higher semantic cohesion (0.3298 vs 0.2952).

Graph 2: `outfolder/module_2_encryption/encryption_line_chart.png`
  - X-Axis: Plaintext payload byte size (100 to 1,000 bytes)
  - Y-Axis: Processing time in milliseconds and output ciphertext bytes
  - Observations: AES-256-GCM adds exactly 28 bytes of overhead (12 IV + 16 Tag) regardless of input
    size. Encryption latency scales linearly and stays below 0.04 ms.

Graph 3: `outfolder/module_4_mmr/mmr_line_chart.png`
  - X-Axis: Number of leaves $N$ (100 to 5,000 chunks)
  - Y-Axis: Generation time (ms) and verification time (ms)
  - Observations: Peak generation scales logarithmically ($O(\log N)$). Verification time remains
    virtually flat (0.032 ms at $N=100$ to 0.068 ms at $N=5,000$), proving that verifier verification
    is scalable to massive enterprise document stores.
