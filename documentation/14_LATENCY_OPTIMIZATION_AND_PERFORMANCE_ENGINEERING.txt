MODULE 14: LATENCY OPTIMIZATION & PERFORMANCE ENGINEERING
================================================================================

1. SYSTEMATIC PROFILING & BOTTLENECK IDENTIFICATION
--------------------------------------------------------------------------------
Initial benchmarking of the raw Privacy RAG implementation revealed that while
security gates functioned correctly, latency was degraded by unoptimized operations:
  - Cold Start Latency: First query took 18-22 seconds due to on-demand loading of the
    SentenceTransformer PyTorch model weights on CPU.
  - LangChain Redundancy: LangChain's generic retriever re-downloaded HuggingFace models
    and executed N+1 HTTP calls, adding 26-45 seconds of retrieval latency.
  - Repeated Collection Scrolling: Redundant Qdrant scroll calls were made on every turn
    to check available documents for intent routing.
  - AES Round-Key Recomputation: `AESGCM(key)` was re-instantiated for every single chunk,
    forcing redundant key expansion.

2. TARGETED ARCHITECTURAL OPTIMIZATIONS
--------------------------------------------------------------------------------

Optimization 1: Lifespan Model Pre-Warming
  - Problem: SentenceTransformer was initialized lazily on the first user query.
  - Solution: In `main.py`, the FastAPI `lifespan(app)` context manager explicitly calls
    `EmbeddingService.get_model()` during server boot. The 384-dimensional model weights
    are loaded into RAM before traffic arrives.
  - Latency Impact: First query cold-start reduced from 18.5s to 0.42s (97.7% reduction).

Optimization 2: LocalEmbeddingAdapter & FlashRank Pipeline
  - Problem: Standard LangChain retrievers re-downloaded models and made HTTP queries per chunk.
  - Solution: Replaced with `LocalEmbeddingAdapter` in `core/langchain_retriever.py`, inheriting
    from `Embeddings` and reusing the in-memory singleton. Extracted `encrypted_content` directly
    from candidate payloads in memory without secondary database lookups.
  - Latency Impact: Retrieval latency dropped from 32s to 27.7 ms.

Optimization 3: In-Memory Document Discovery Cache with TTL
  - Problem: Intent routing performed Qdrant `.scroll()` calls on every user keystroke.
  - Solution: Added `_DOCS_CACHE: Dict[str, Tuple[float, List[Dict[str, Any]]]]` in `main.py`
    with a 60-second time-to-live (TTL). Invalidated immediately upon new document ingestion.
  - Latency Impact: Eliminated 15-25 ms of database overhead on subsequent turns.

Optimization 4: Cryptographic Key-Expansion & MMR Proof Memoization
  - Problem: Recomputing AES round-keys and climbing identical cloud MMR proof paths.
  - Solution: Added `@lru_cache` to `crypto/encryption.py` for key expansion and memoized
    recomputed MMR roots in `mmr/proof.py`.
  - Latency Impact: Chunks decrypted at 0.0104 ms each; MMR proofs verified in 0.025-0.068 ms.

Optimization 5: SQLite Connection Management
  - Problem: Unclosed database connections caused SQLite thread contention and lock wait warnings.
  - Solution: Replaced raw connection calls with context-managed `@contextlib.contextmanager`
    pools in `AuthService` and `ConversationService`.
  - Latency Impact: Database lookup and write overhead dropped to under 1.2 ms.
