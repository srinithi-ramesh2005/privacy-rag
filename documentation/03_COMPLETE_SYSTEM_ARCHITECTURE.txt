2. PHYSICAL LAYER ARCHITECTURE
--------------------------------------------------------------------------------
1. Web Client: Modern browser executing clientside DOM operations, state management,
   and theme rendering without Node.js dependencies.
2. Web & API Server: Python 3.13 / FastAPI process running on `http://localhost:8000`.
   Manages routing, cryptographic proofs, and pipeline coordination.
3. Vector Database Service: Qdrant service running on port 6333 (HTTP) and 6334 (gRPC).
   Maintains HNSW and IVF vector indices with encrypted payloads.
4. Relational Database: SQLite 3 engine accessing `storage_data/auth.db` via transactional
   context managers with connection timeout controls.
5. Machine Learning Models:
   - Primary Embedding Model: `BAAI/bge-small-en-v1.5` (384 dimensions, ~133 MB).
   - Reranking Cross-Encoder: `cross-encoder/ms-marco-MiniLM-L-6-v2` (~80 MB).
   - Document Compressor: `FlashrankRerank` (Rank-1 context compression).
   - Primary Generative LLM: Groq Cloud API hosting Llama-3.3-70B-Versatile.

3. ARCHITECTURAL SEPARATION OF CONCERNS
--------------------------------------------------------------------------------
- Ingestion Separation: Ingestion parses, chunks, encrypts, and builds MMR trees once.
  Once committed, the cloud enterprise root is signed and stored.
- Retrieval Decoupling: Vector retrieval locates candidate IDs based on mathematical
  similarity in embedding space. The vector store cannot read document content.
- Verification Isolation: Verification is executed by client/server verifiers before
  plaintext is reconstructed. Decryption keys never reside on the vector database server.
